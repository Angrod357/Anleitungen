Vorbereitung
Systemvoraussetzungen prüfen
Theorie

RAM4 GB16 GB (8 GB für Host + 8 GB für VMs)

⚠️
Virtualisierung muss im BIOS/UEFI aktiviert sein. BIOS → Advanced → CPU → Intel VT-x oder AMD-V → Enabled. Ohne dies startet keine VM.

DHCP einrichten
Rolle installieren, Bereich (Scope) erstellen und automatische IP-Vergabe aktivieren.
Theorie
Was macht DHCP?
Basiswissen
📌
DHCP (Dynamic Host Configuration Protocol) vergibt IP-Adressen, Subnetzmaske, Gateway und DNS-Server automatisch an Clients im Netzwerk. Ohne DHCP müsste jeder Client manuell konfiguriert werden.
DORA-ProzessBeschreibung
DiscoverClient sendet Broadcast: "Gibt es einen DHCP-Server?"
OfferServer antwortet mit einem IP-Angebot
RequestClient nimmt das Angebot an und fordert die IP an
AcknowledgeServer bestätigt und trägt Lease-Eintrag ein

MXMail-Server der Domainmail.firma.local

Heim-NAS mit Raspberry Pi
Eigene Cloud zuhause aufbauen — Dateien zentral speichern, von überall per VPN zugreifen, komplett unter eigener Kontrolle.
Warum ein NAS?
Wofür ist ein Heim-NAS gut?
Erklärung

Ein NAS (Network Attached Storage) ist ein Netzwerkspeicher — ein kleiner Computer, der rund um die Uhr läuft und Dateien für alle Geräte im Heimnetz (und von unterwegs) bereitstellt. Statt Fotos, Videos und Dokumente bei Google, Dropbox oder iCloud zu speichern, liegen deine Daten auf deiner eigenen Hardware — niemand sonst hat Zugriff.

AnwendungsfallBeschreibungErsetzt
📁 Dateiserver Alle Geräte greifen auf denselben Ordner zu — kein USB-Stick mehr Dropbox, OneDrive
📸 Foto-Backup Handy-Fotos werden automatisch auf das NAS gesichert Google Fotos, iCloud
🎬 Media-Server Filme & Musik auf TV, Tablet oder Handy streamen Plex, Netflix-Abo
🔒 Backup-Ziel Automatische Sicherung aller PCs im Heimnetz Externe Festplatten
☁️ Private Cloud Nextcloud: Kalender, Kontakte, Dateien synchronisieren Google Workspace
🌍 Fernzugriff per VPN Von unterwegs sicher auf alle Dateien zuhause zugreifen Cloud-Abonnements
💡
Ein Raspberry Pi 4 (4 GB) mit einer 2-TB-USB-Festplatte läuft mit ca. 3–5 Watt — das sind rund 3–4 CHF pro Monat Stromkosten. Kommerzielle NAS-Systeme (Synology, QNAP) kosten 200–500 CHF und haben deutlich höheren Verbrauch.

Kernstück

Wofür
Was macht Pi-hole?
Erklärung

Pi-hole ist ein DNS-Sinkhole. Statt Werbung herunterzuladen, antwortet Pi-hole auf Anfragen an bekannte Werbe- und Tracking-Domains einfach mit 0.0.0.0 — die Verbindung wird gar nicht erst aufgebaut. Das funktioniert für alle Geräte im Netz gleichzeitig: Handy, TV, Laptop, Spielekonsole — ohne App-Installation.

📊
Typische Heimnetze blockieren 15–30 % aller DNS-Anfragen. Das bedeutet weniger Bandbreite, schnellere Ladezeiten und keine Werbe-Tracker mehr auf dem Handy.

IPv4-Adressen verstehen
Theorie

Eine IPv4-Adresse besteht aus 4 Oktetts (je 8 Bit = 0–255), getrennt durch Punkte. Zusammen mit der Subnetzmaske legt sie fest welcher Teil die Netzwerkadresse und welcher die Hostadresse ist.

Windows 0x0000007B · INACCESSIBLE_BOOT_DEVICE
Ursache: Windows findet beim Start den Boot-Treiber nicht — oft nach Hardwarewechsel oder falschem AHCI/IDE-Modus im BIOS.
Lösung: BIOS → SATA-Mode auf AHCI stellen. Oder Reparatur-CD → bootrec /rebuildbcd
Windows 0xC000021A · STATUS_SYSTEM_PROCESS_TERMINATED
Ursache: Kritischer Systemfehler, oft durch defekte Windows-Systemdateien oder fehlerhafte Updates.
Lösung: WinRE → sfc /scannow → DISM /Online /Cleanup-Image /RestoreHealth
Windows Error 0x80070005 · ACCESS_DENIED
Ursache: Fehlende Berechtigungen — oft bei Windows Update, Softwareinstallation oder Dateizugriff.
Lösung: Als Administrator ausführen. UAC prüfen. Ordner-Berechtigungen in Eigenschaften → Sicherheit korrigieren.
Windows Error 0x80073701 · Update-Fehler
Ursache: Windows Update Component Store beschädigt.
Lösung: DISM /Online /Cleanup-Image /RestoreHealth → danach sfc /scannow → Windows Update erneut starten.
Windows Fehler 1068 · Abhängiger Dienst
Ursache: Ein Dienst konnte nicht gestartet werden, weil ein abhängiger Dienst gestoppt ist.
Lösung: services.msc → Abhängigkeiten des Dienstes prüfen → fehlende Dienste manuell starten.
Windows 0x80004005 · Unspecified Error
Ursache: Allgemeiner Fehler — tritt bei VM-Zugriff, Netzwerkfreigaben oder Updates auf.
Lösung: Kontext-abhängig: bei VMs Gasterweiterungen neu installieren; bei Freigaben Anmeldedaten in der Credential-Verwaltung löschen.
Windows RPC-Server nicht verfügbar (1722)
Ursache: RPC-Dienst gestoppt oder Firewall blockiert RPC-Traffic.
Lösung: services.msc → Remote Procedure Call prüfen. Firewall: Remote Procedure Call Regel aktivieren.
Linux Permission denied (publickey)
Ursache: SSH-Key nicht auf dem Server hinterlegt oder falsche Berechtigungen auf ~/.ssh/.
Lösung: ssh-copy-id user@server · Berechtigungen: chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
Linux E: Could not get lock /var/lib/dpkg/lock
Ursache: Ein anderer apt-Prozess läuft noch (oder ist abgestürzt und hat die Lock-Datei hinterlassen).
Lösung: sudo rm /var/lib/dpkg/lock-frontend && sudo dpkg --configure -a
Linux No space left on device
Ursache: Festplatte voll — oft durch Logs, Docker-Images oder alte Kernel.
Lösung: df -h → du -sh /* → journalctl --vacuum-size=100M · Docker: docker system prune -a
Linux systemctl: Unit not found
Ursache: Dienst nicht installiert oder Unit-Datei nicht vorhanden.
Lösung: systemctl list-units --all | grep dienstname · Paket prüfen: dpkg -l | grep paketname
Linux Kernel panic - not syncing
Ursache: Kritischer Kernel-Fehler — defekte Hardware, fehlender Treiber oder beschädigtes Dateisystem.
Lösung: Boot mit älterem Kernel (GRUB Advanced Options). Dateisystem prüfen: fsck /dev/sda1 im Recovery-Modus.
Linux Failed to start — see journalctl -xe
Ursache: Ein systemd-Dienst ist beim Start fehlgeschlagen.
Lösung: journalctl -u dienstname -n 50 für genaue Fehlermeldung. Konfigurationsdatei prüfen und korrigieren.
Netzwerk Connection timed out
Ursache: Host nicht erreichbar — Firewall blockiert, Host aus, falscher Port oder falsche IP.
Lösung: ping ziel-ip → nmap -p port ziel-ip · Firewall-Regeln beider Seiten prüfen.
Netzwerk Connection refused
Ursache: Host ist erreichbar, aber der Port ist nicht offen — Dienst läuft nicht oder falsche Portnummer.
Lösung: ss -tlnp | grep port · Dienst starten: systemctl start dienstname
Netzwerk APIPA Adresse 169.254.x.x
Ursache: DHCP-Server nicht erreichbar — Gerät hat sich selbst eine Link-Local-Adresse vergeben.
Lösung: DHCP-Server prüfen (systemctl status dhcpd). Client: ipconfig /release && ipconfig /renew
Netzwerk DNS_PROBE_FINISHED_NXDOMAIN
Ursache: Domain existiert nicht oder DNS-Server kann sie nicht auflösen.
Lösung: nslookup domain.ch 8.8.8.8 testen. DNS-Einstellung prüfen: ipconfig /all · DNS-Cache leeren: ipconfig /flushdns
Netzwerk Duplicate IP Address detected
Ursache: Zwei Geräte haben dieselbe IP — oft bei manuell gesetzter IP und gleichzeitig laufendem DHCP.
Lösung: arp -a → Konflikt-Gerät identifizieren. DHCP-Ausschluss für statische IPs konfigurieren.
HTTP 400 Bad Request
Ursache: Der Client hat eine fehlerhafte Anfrage gesendet — ungültige Header, zu grosse Cookies oder falsche Syntax.
Lösung: Browser-Cache und Cookies löschen. Bei API: Request-Header und Body prüfen.
HTTP 401 Unauthorized
Ursache: Keine oder falsche Authentifizierung — kein Token, abgelaufene Session oder falsche Zugangsdaten.
Lösung: Erneut einloggen / Token erneuern. Bei API: Auth-Header Authorization: Bearer TOKEN prüfen.
HTTP 403 Forbidden
Ursache: Authentifiziert, aber keine Berechtigung für diese Ressource — Benutzerrechte oder Webserver-Konfiguration.
Lösung: Datei-/Ordnerberechtigungen prüfen (chmod 755). Nginx/Apache-Konfiguration prüfen.
HTTP 404 Not Found
Ursache: Ressource nicht gefunden — falsche URL, gelöschte Datei oder fehlende Route.
Lösung: URL prüfen. Webserver-Logs: tail -f /var/log/nginx/error.log · Webserver-Konfiguration (document root, Aliase).
HTTP 500 Internal Server Error
Ursache: Allgemeiner Serverfehler — Anwendungsfehler, fehlerhafte Konfiguration oder Speichermangel.
Lösung: Anwendungs-Logs prüfen. journalctl -u nginx oder App-spezifische Logs in /var/log/
HTTP 502 Bad Gateway
Ursache: Reverse Proxy (Nginx) kann den Backend-Dienst nicht erreichen — Backend läuft nicht oder falscher Port.
Lösung: Backend-Dienst prüfen: systemctl status app · Proxy-Ziel in Nginx-Config prüfen (proxy_pass).
HTTP 503 Service Unavailable
Ursache: Dienst überlastet oder in Wartung — zu viele gleichzeitige Verbindungen oder Upstream nicht bereit.
Lösung: Serverlast prüfen: top / htop. Dienst neu starten. Nginx: worker_processes und worker_connections prüfen.

Theorie
Was ist eine Shell?
Basiswissen

Wie die meisten modernen Betriebssysteme stellt auch Linux zwei Schnittstellen für Benutzereingaben zur Verfügung: die grafische Benutzeroberfläche (GUI) und die Shell. Die Shell ist ein Programm, das als Schnittstelle zwischen System und Benutzer fungiert — sie nimmt Tastatureingaben entgegen, wertet diese aus, startet Programme und gibt die Ausgabe als Text zurück.

📌
Jede Shell besitzt eine eigene Programmiersprache, die es ermöglicht, Shell-Skripte zu schreiben — z.B. um Programmaufrufe zu verknüpfen und administrative Aufgaben zu automatisieren.

Befehlssyntax — Grundregeln
Wichtig

Jede Eingabe in der Shell folgt einem festen Schema. Abweichungen führen zu Fehlermeldungen.

BEFEHL [OPTIONEN] [ARGUMENTE] # Beispiele: $ ls ← Befehl allein $ ls -l ← Befehl + Kurzoptionen (ein Bindestrich) $ ls --all ← Befehl + Langoption (zwei Bindestriche) $ ls -l /home/student ← Befehl + Option + Argument (Pfad) $ ls -la /home/student ← mehrere Optionen zusammen
ElementBeschreibungBeispiel
BefehlName des Programms / Built-in-Befehlsls, cd, mkdir
KurzoptionenEin Bindestrich + ein Buchstabe, kombinierbar-l, -a, -la
LangoptionenZwei Bindestriche + Wort, nicht kombinierbar--all, --help
ArgumenteDateien, Verzeichnisse oder Werte die der Befehl verarbeitet/home/student
⚠️
Linux ist case-sensitive: ls und LS sind verschiedene Befehle. cal funktioniert, Cal nicht. Leerzeichen zwischen Befehl, Optionen und Argumenten sind zwingend erforderlich.

01
Tab-Vervollständigung — weniger tippen, weniger Fehler
Grundtechnik

Je länger eine Befehlszeile, desto wahrscheinlicher sind Tippfehler. Die Bash hilft dir dabei: Wenn du einen Datei- oder Verzeichnisnamen eingibst und Tab drückst, vervollständigt die Shell den Namen automatisch — sofern er eindeutig ist. Das spart Zeit und verhindert Fehler bei langen Pfadnamen.

⌨️
Wie es funktioniert: Die Bash durchsucht das Dateisystem nach allen Einträgen, die mit deiner bisherigen Eingabe beginnen. Gibt es genau einen Treffer, wird er sofort eingesetzt. Gibt es mehrere, passiert beim ersten Tab nichts — beim zweiten Tab zeigt die Shell alle Möglichkeiten an.

Beispiel 1 — eindeutige Vervollständigung

# Eingabe: cat /pr → Tab drücken → Tab drücken $ cat /pr[Tab]cp[Tab] # Was passiert: # /pr → wird zu /proc (einziges Verzeichnis, das mit "pr" beginnt) # cp → wird zu /proc/cpuinfo (nach weiterer Eingabe) # Ergebnis: cat /proc/cpuinfo # → zeigt Informationen über deinen Prozessor

Beispiel 2 — mehrere Treffer anzeigen

# Eingabe: cat /e → Tab → i → Tab → Tab $ cat /e[Tab]i[Tab][Tab] # Was passiert: # /e → wird zu /etc/ (eindeutig) # i → mehrere Treffer: init.d/, initramfs-tools/, … # Beim zweiten Tab werden ALLE Möglichkeiten aufgelistet
✅
Faustregel: Tippe genug Zeichen für Eindeutigkeit, dann Tab. Wenn nichts passiert — nochmal Tab für alle Optionen. Das geht auch für Befehle selbst: sys + Tab zeigt alle Befehle, die mit "sys" beginnen.
02
History — Befehle zurückholen und wiederverwenden
Effizienz

Die Bash speichert die letzten 500–1000 eingegebenen Befehle in einer sogenannten History-Datei (~/.bash_history). Das ist nützlich, wenn du denselben oder einen ähnlichen Befehl nochmals ausführen willst — ohne ihn komplett neu tippen zu müssen.

Methode A — Pfeiltasten

TasteAktionWarum nützlich
↑Vorheriger BefehlLetzten Befehl nochmals ausführen oder anpassen
↓Nächster BefehlVorwärts in der History navigieren
EnterAusführenBefehl so ausführen wie angezeigt

Methode B — History durchsuchen mit Strg+R

# Rückwärtssuche in der History [Strg+R] # Suchbegriff eingeben, z.B. "touch" # → letzten passenden Befehl sofort anzeigen # → Enter: ausführen | Strg+R: weiteren älteren suchen | ESC: abbrechen

Methode C — history-Befehl

# Alle gespeicherten Befehle anzeigen (nummeriert) $ history # Nur die letzten 10 Befehle anzeigen $ history 10 # History nach einem Begriff durchsuchen $ history | grep touch # Einen bestimmten Befehl per Nummer direkt ausführen $ !42 ← Befehl Nr. 42 aus der History ausführen $ !! ← Letzten Befehl nochmals ausführen

Praxisbeispiel — ähnliche Dateien erstellen ohne neu tippen

# Erste Datei erstellen $ touch neuedatei1 # Pfeiltaste ↑ → Befehl erscheint wieder # Cursor mit ← an die "1" navigieren, auf "2" ändern → Enter $ touch neuedatei2 # Nochmals ↑ → "2" auf "3" ändern → Enter $ touch neuedatei3 # Ergebnis prüfen $ ls -l neuedatei*
💡
Mit Strg+A springst du an den Zeilenanfang, mit Strg+E ans Ende. Mit Strg+W löschst du das Wort vor dem Cursor. Diese Shortcuts sparen viel Zeit bei langen Befehlen.
03
Man-Pages — die eingebaute Dokumentation
Nachschlagen

Linux hat tausende von Befehlen — jeder mit eigenen Optionen und Parametern. Kein Mensch kann sich alle merken. Deshalb gibt es die Manual-Pages (Man-Pages): eine eingebaute Dokumentation, die direkt im Terminal verfügbar ist. Bevor du etwas googelst, lohnt es sich fast immer, zuerst man aufzurufen — die Antwort ist meistens schon dort.

Man-Page aufrufen

# Hilfe zu einem bestimmten Befehl $ man ls $ man cp $ man pwd # Man-Page über man selbst — erklärt wie man man benutzt $ man man

04
Befehl suchen, wenn du den Namen nicht kennst
Recherche

Manchmal weisst du, was du tun willst — aber nicht, welcher Befehl dafür zuständig ist. Beispiel: Du suchst einen Befehl für Backups, weisst aber nicht ob er backup, archive, rsync oder anders heisst. Dafür gibt es apropos und man -k.

# Alle Man-Pages nach einem Stichwort durchsuchen $ apropos backup $ apropos compress $ apropos network # Identisch mit apropos — beides macht dasselbe $ man -k backup # Kurzbeschreibung eines bekannten Befehls anzeigen $ whatis tar $ whatis ls
💡
Wie apropos funktioniert: Es durchsucht nicht das Dateisystem, sondern eine Datenbank aller Man-Pages nach dem Begriff in Titel und Kurzbeschreibung. Die Ausgabe listet alle Treffer mit Kurzbeschreibung auf — du erkennst sofort, welcher Befehl das Richtige sein könnte.
# Beispiel-Output von: apropos backup # rsync (1) - a fast, versatile, remote (and local) file-copying tool # tar (1) - an archiving utility # dump (8) - ext2/3/4 filesystem backup # restore (8) - restore files or file systems from backups made with dump # Danach gezielt die passende Man-Page aufrufen $ man rsync

06
Weitere Wege zur Hilfe
Überblick
--help
Fast jeder Befehl kennt die Option --help oder -h. Sie gibt eine kompakte Übersicht der wichtigsten Optionen aus — schneller als die Man-Page, aber weniger ausführlich.
$ ls --help $ cp --help | less ← bei langer Ausgabe mit less lesen
help
Der Befehl help zeigt Hilfe zu eingebauten Shell-Befehlen (built-ins) wie cd, echo oder alias. Diese haben keine eigene Man-Page, weil sie Teil der Shell selbst sind.
$ help cd $ help echo $ help ← alle built-ins auflisten
info
info zeigt GNU Info-Seiten — ähnlich wie Man-Pages, aber mit Verlinkungen und oft noch ausführlicher. Besonders für GNU-Tools wie tar, grep, bash.
$ info bash $ info tar
🎯
Empfohlene Reihenfolge beim Nachschlagen:
1. befehl --help → schneller Überblick der Optionen
2. man befehl → vollständige Dokumentation mit Erklärungen
3. apropos stichwort → wenn du den Befehlsnamen nicht kennst
4. Internet → wenn auch die Man-Pages nicht weiterhelfen

Wie du dich im Linux-Dateisystem bewegst, Verzeichnisse und Dateien verwaltest und Dateien systemweit findest — mit Erklärungen zu Struktur und Berechtigungen.

Kontext
Warum das Dateisystem so wichtig ist
Hintergrund

In Linux dreht sich alles rund um Dateien. Konfigurationen, Logs, Gerätetreiber, Prozessinformationen — all das ist im Dateisystem abgebildet. Als Systemadministrator musst du dich darin orientieren können: du musst wissen wo Konfigurationsdateien liegen, wie du Verzeichnisse anlegst und wieder aufräumst, und wie du eine bestimmte Datei findest, wenn du ihren genauen Speicherort vergessen hast.

📌
Typisches Szenario: Du schreibst ein Skript, das eine Systemdatei liest. Bevor du die Originaldatei veränderst, machst du zuerst eine Kopie als Backup — und legst Testdateien an, um dein Skript gefahrlos zu prüfen. Wenn alles funktioniert, räumst du die Testdateien wieder weg.
01
Das Arbeitsverzeichnis — wo bin ich gerade?
Navigation

Jede Terminal-Sitzung startet in einem bestimmten Verzeichnis — dem Arbeitsverzeichnis. Nach der Anmeldung ist das normalerweise dein Home-Verzeichnis (/home/benutzername). Alle relativen Pfade, die du angibst, beziehen sich auf dieses aktuelle Verzeichnis.

# Aktuelles Arbeitsverzeichnis anzeigen (print working directory) $ pwd # Ausgabe: /home/student1
Pfad-NotationBedeutungBeispiel
/Wurzelverzeichnis (root) — oberste Ebene/etc/passwd
~Home-Verzeichnis des aktuellen Benutzers~/skripts
.Aktuelles Verzeichnis./meinskript.sh
..Übergeordnetes Verzeichnis (eine Ebene hoch)../ziel/
# Verschiedene Wege ins Home-Verzeichnis zurückzukehren $ cd ~ ← Home-Verzeichnis (immer funktioniert) $ cd ← ohne Argument = Home (Kurzform) $ cd /home/student1 ← absoluter Pfad $ cd .. ← eine Ebene nach oben $ cd - ← zurück zum vorherigen Verzeichnis
💡
Relativer vs. absoluter Pfad: Ein absoluter Pfad beginnt immer mit / und funktioniert von überall. Ein relativer Pfad bezieht sich auf das aktuelle Verzeichnis und ist kürzer zu tippen — aber nur dann korrekt, wenn du im richtigen Verzeichnis bist.
02
Verzeichnisse erstellen und prüfen
mkdir · ls

Mit mkdir (make directory) legst du neue Verzeichnisse an. Du kannst eines nach dem anderen erstellen — oder mehrere auf einmal. Nach dem Erstellen solltest du immer mit ls -l kontrollieren, ob es funktioniert hat.

# Einzeln erstellen $ mkdir privat $ mkdir skripts $ mkdir diverses # Alle drei auf einmal — das Gleiche, in einer Zeile $ mkdir privat skripts diverses # Verschachtelte Verzeichnisse auf einmal erstellen (-p = parents) $ mkdir -p projekte/2024/januar # Erstellt alle Ebenen, auch wenn "projekte" noch nicht existiert

Kontrolle: Wurden die Verzeichnisse wirklich erstellt?

# ls -l zeigt den Inhalt mit Details — Verzeichnisse erkennst du am "d" am Anfang $ ls -l # drwxr-xr-x 2 student1 users 4096 Mai 12 10:15 diverses # drwxr-xr-x 2 student1 users 4096 Mai 12 10:15 privat # drwxr-xr-x 2 student1 users 4096 Mai 12 10:15 skripts # Das "d" ganz links = Directory (Verzeichnis) # Ein "-" ganz links = normale Datei
📌
Was bedeuten die Zeichen in ls -l? Der erste Buchstabe zeigt den Typ: d = Verzeichnis, - = Datei, l = symbolischer Link. Die folgenden 9 Zeichen sind die Berechtigungen in drei Gruppen: Besitzer / Gruppe / Alle anderen.
03
Dateiberechtigungen lesen und verstehen
Konzept

Jede Datei und jedes Verzeichnis in Linux hat Berechtigungen, die genau festlegen, wer was damit machen darf. Das ist eines der zentralen Konzepte von Linux-Sicherheit.

# Neue leere Datei erstellen und Berechtigungen anschauen $ cd privat $ touch meinedatei $ ls -l meinedatei # -rw-r--r-- 1 student1 users 0 Mai 12 10:20 meinedatei
PositionZeichenBedeutung
1-Typ: - = Datei, d = Verzeichnis, l = Link
2–4rw-Besitzer: lesen (r) + schreiben (w), kein Ausführen
5–7r--Gruppe: nur lesen (r)
8–10r--Alle anderen: nur lesen (r)
—student1Besitzer der Datei
—usersGruppe, der die Datei gehört
🔐
r, w, x im Überblick: r (read) = lesen, w (write) = schreiben/ändern, x (execute) = ausführen. Ein - bedeutet: diese Berechtigung ist nicht vorhanden. Bei Verzeichnissen bedeutet x: du darfst das Verzeichnis betreten (cd).
# Berechtigungen ändern mit chmod # Besitzer darf ausführen hinzufügen $ chmod u+x meinedatei # Numerisch: 7=rwx, 6=rw-, 5=r-x, 4=r--, 0=--- $ chmod 644 meinedatei ← rw-r--r-- (Standard für Dateien) $ chmod 755 skript.sh ← rwxr-xr-x (ausführbares Skript)
04
Dateien erstellen, kopieren, verschieben, umbenennen, löschen
Dateiverwaltung

Leere Dateien erstellen mit touch

touch erstellt eine leere Datei — ohne Inhalt. Das ist nützlich für Testzwecke oder um zu prüfen, ob ein Skript Dateien korrekt erkennt. Mehrere Dateien auf einmal:

$ cd /home/student1 $ mkdir quelle ziel $ cd quelle $ touch doku1 doku2 doku3 doku4 doku5 $ ls # doku1 doku2 doku3 doku4 doku5

Dateien löschen mit rm

rm löscht Dateien unwiderruflich — kein Papierkorb, keine Bestätigung. Deshalb gibt es -i für interaktives Löschen mit Rückfrage:

# Direkt löschen — keine Rückfrage $ rm doku1 doku2 # Interaktiv löschen — System fragt vorher nach $ rm -i doku3 # rm: reguläre leere Datei 'doku3' entfernen? j # → 'j' für ja, 'n' für nein, Enter bestätigt # Warum -i? Tipp aus der Man-Page: # man rm → DESCRIPTION → -i, --interactive: Vor jeder Entfernung nachfragen
⚠️
rm -rf verzeichnis/ mit Vorsicht verwenden! Das löscht ein Verzeichnis mit allem was drin ist — sofort, ohne Rückfrage. Als Root kann das das ganze System beschädigen. Im Zweifel zuerst -i verwenden.

Umbenennen und Verschieben mit mv

mv (move) macht beides: Umbenennen und Verschieben. Innerhalb desselben Verzeichnisses = Umbenennung. Anderes Zielverzeichnis = Verschieben.

# Umbenennen $ mv doku4 dokument4 $ mv doku5 dokument5 # In anderes Verzeichnis verschieben (absoluter Pfad) $ mv dokument4 dokument5 /home/student1/ziel # Dasselbe mit relativem Pfad (eine Ebene hoch, dann in "ziel") $ mv dokument4 dokument5 ../ziel # Ergebnis prüfen $ ls ../ziel # dokument4 dokument5
05
Verzeichnisse löschen — rmdir vs. rm -r
Wichtig

Es gibt zwei Befehle zum Löschen von Verzeichnissen — mit einem wichtigen Unterschied: rmdir funktioniert nur bei leeren Verzeichnissen. Das ist eigentlich ein Sicherheitsnetz: du kannst nichts aus Versehen löschen.

# Leeres Verzeichnis löschen — klappt problemlos $ rmdir diverses # Kein Output = Erfolg. Linux gibt keine Bestätigung aus. # Nicht-leeres Verzeichnis löschen — schlägt fehl mit Erklärung $ rmdir privat # rmdir: privat: Das Verzeichnis ist nicht leer # → Das System schützt dich vor versehentlichem Datenverlust # Verzeichnis MIT Inhalt löschen: rm -r (rekursiv) $ rm -r privat # Löscht "privat" und ALLES darin — keine Rückfrage! # Sicherer: mit -i kombinieren $ rm -ri privat # Fragt für jede Datei und jedes Unterverzeichnis nach
💡
Warum gibt Linux keine Bestätigungsmeldung nach erfolgreichem Löschen? Unix-Philosophie: «no news is good news». Wenn kein Fehler erscheint, hat der Befehl funktioniert. Nur Fehler werden gemeldet. Das spart Bildschirmplatz bei Skripten, die hunderte Dateien verarbeiten.
06
Dateien im System finden mit find
Suche

Das Linux-Dateisystem enthält Tausende von Dateien. Konfigurationsdateien, Logdateien, ausführbare Programme — wenn du nicht mehr weisst wo etwas liegt, hilft find. Anders als locate durchsucht find das Dateisystem live — also immer aktuell.

Syntax und wichtige Optionen

# Grundschema # find [STARTVERZEICHNIS] [SUCHKRITERIUM] [AKTION] # Datei nach Name suchen (Gross/Kleinschreibung beachten) $ find / -name "hostname" 2>/dev/null # 2>/dev/null leitet Fehlermeldungen weg (z.B. "Permission denied") # → /etc/hostname # Mit Platzhalter: alle Dateien die mit "ssh" beginnen $ find / -name "ssh*" 2>/dev/null # Nur in einem bestimmten Verzeichnis suchen $ find /usr/bin -name "*sh*" # Findet Shells und Hilfsprogramme die "sh" im Namen haben # /usr/bin/bash /usr/bin/dash /usr/bin/sh /usr/bin/zsh … # Dateien die heute geändert wurden $ find /home/student1 -mtime -1 # -mtime -1 = in den letzten 24 Stunden geändert # Dateien nach Grösse suchen (grösser als 100 KB) $ find /var/log -size +100k
OptionBedeutungBeispiel
-nameNach Dateiname (mit Wildcards)-name "*.conf"
-inameWie -name, aber Gross/Klein egal-iname "readme*"
-type fNur Dateien (file)-type f -name "*.sh"
-type dNur Verzeichnisse-type d -name "log*"
-mtime -1In den letzten 24h geändert-mtime -7 (letzte Woche)
-size +1MGrösser als 1 MB-size +100M
-user nameGehört einem bestimmten Benutzer-user student1

Shells im System finden

Die meisten ausführbaren Programme liegen in /usr/bin und /usr/sbin. So findest du alle installierten Shells:

$ find /usr/bin -name "*sh*" # /usr/bin/bash ← Bourne Again Shell # /usr/bin/dash ← Debian Almquist Shell # /usr/bin/sh ← Standard POSIX Shell # /usr/bin/zsh ← Z Shell (falls installiert) # + weitere Tools die "sh" im Namen haben (ssh, chsh, …) $ find /usr/sbin -name "*sh*" # /usr/sbin/sshd ← SSH-Daemon (Server) # /usr/sbin/add-shell, /usr/sbin/remove-shell … # Ob ein Treffer wirklich eine Shell ist → Man-Page prüfen $ man bash $ man dash
📌
Warum 2>/dev/null? Beim Durchsuchen von / (Wurzelverzeichnis) stösst find auf Verzeichnisse, auf die du keinen Zugriff hast — es erscheinen Fehlermeldungen wie Permission denied. Mit 2>/dev/null lenkst du diese Fehlermeldungen in den digitalen Papierkorb (/dev/null) und siehst nur die echten Suchergebnisse.
